## A–H: 수정 전 진단과 선택

사용자는 구체와 작은 Assistant 패널을 먼저 보고, Context를 열어 파일을 고른 뒤 다시 입력창으로 돌아온다. 요청 후 작업 생성 승인을 하고 파일 연결을 별도로 선택한다. 재개 브리핑에서 시작을 누르면 현재 작업과 관련 파일이 열린다. Main에서 PiP로 가는 행동은 이름 없는 구체 클릭에 숨어 있었다.

실제 영향 순으로 발견한 문제는 다음과 같다. 확신은 모두 높음(코드·Electron 스크린샷·클릭 근거).

1. 화면 대부분이 장식과 여백이고 본문·입력·브리핑 글씨가 작았다. 사용자 시선이 실제 작업보다 장식에 먼저 갔다.
2. 파일 편집기가 탐색 패널의 조상 요소에 의해 잘렸다. 코드 주석에는 body 포털이라고 쓰여 있었지만 실제 구현은 포털이 아니었다.
3. 프로젝트·현재 작업·파일이 반복 표시되면서 역할이 구분되지 않았다. 빈 브리핑과 빈 활동 목록도 항상 공간을 차지했다.
4. 구체가 PiP 전환 버튼이라는 설명이 없고, PiP에서는 두 구체와 완료 카드가 겹쳤다.
5. JSX 주석 문법 오류로 개발 메모가 사용자 화면에 그대로 노출됐다.

우선순위는 읽고 입력할 공간 확보, 문맥·다음 행동 정리, PiP 역할 분리의 세 가지로 묶었다. 첫째는 매번 읽기와 입력을 방해하고, 둘째는 사용자가 상태를 기억해야 하며, 셋째는 화면을 전환하는 방법을 추측하게 하기 때문이다.

수정 전: 장식 중심 화면 → 작은 Context → 잘린 파일 → 떨어진 입력 → 승인 → 연결.

수정 후: Assistant 영역 → 이름이 보이는 ‘작업 · 파일’ → 옆의 온전한 파일 → 하단 입력 → 기존 승인·연결. 재개는 ‘다음 행동’과 ‘이어서 작업’으로 표시한다.

이번 범위에서 하지 않은 것: 모델 교체, 자동 승인, 자동 파일 연결, 새 데이터 구조, 새 상위 메뉴, 전체 번역, 음성 성능 변경.

## I–M: 개선과 검증

가장 큰 개선 세 가지:

1. Assistant와 파일이 나란히 공간을 확보한다. 파일 편집기는 body 포털로 렌더되어 잘리지 않는다. 답변만 스크롤되고 입력창은 남는다.
2. 프로젝트 / 현재 작업 / 활성 파일의 표시를 구분한다. 헤더의 중복 작업·파일 이름, 빈 실행 기록, 반복되는 빈 작업 설명, 개발 주석 노출을 정리했다.
3. PiP의 두 구체를 하나로 줄이고 상태·응답 보기·요청 입력을 겹치지 않게 배치했다. Main의 전환 동작에는 설명을 붙였다.

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| 빈 작업 상태 첫 화면 버튼 | 7 | 5 |
| 파일 선택→요청→승인→연결 | 5클릭 | 5클릭 |
| ‘계속하자’ 입력창 선택→전송→시작 | 3클릭 | 3클릭 |
| PiP 구체 중심 클릭 적중 | 완료 카드에 가려짐 | 구체 자체에 적중 |
| PiP 구체 수 | 2 | 1 |

클릭 수는 줄지 않았다. B 흐름의 5클릭은 기존 감사 스크립트처럼 텍스트 입력을 위한 포커스 클릭을 제외한 수치다. C는 입력 포커스 클릭을 포함하므로 B와 C를 서로 비교하는 값이 아니다. 수정 전후 각각 동일한 측정법을 사용했다. 자동 복귀 브리핑은 이미 존재하던 기능이며 이번에 새로 만든 기능이 아니다.

실행 앱에서 아래 명령을 실행했다.

```powershell
npm run build
npm run lint
node tests/verify_workspace_ux.cjs
```

모두 종료 코드 0. 실제 Electron에서 파일 열기·요청·승인·연결·재개·Main↔PiP 왕복을 실행했다. 1280×800과 900×800 렌더링에서 Assistant/파일의 비중첩과 화면 경계, 입력·전송·파일 내용·구체의 클릭 적중을 단정문으로 검사했다. 탐색 패널을 닫아도 파일이 남고 Escape가 파일부터 닫는 것도 확인했다. PiP는 구체·결과·입력의 클릭 적중을 확인했다.

전체 `git diff --check`는 기존 `electron/preload.cjs` 변경의 공백 경고를 보고했다. 이번 수정 대상 7개 소스의 별도 검사 결과는 깨끗하다. 기존 변경을 정리하기 위해 해당 파일을 재작성하지 않았다.

남은 가장 큰 불편: 작업 생성 승인 이후 파일 연결을 별도로 선택해야 한다. 승인 화면에서 ‘이 파일도 연결’이라는 명시적 선택을 제공하는 방향은 다음 개선 후보이며 아직 구현하지 않았다. 실제 모델 응답 품질, 음성 장치, 모든 오류·승인 종류의 PiP 화면, 900px 미만 Main 화면은 이번 검증 범위 밖이다.
